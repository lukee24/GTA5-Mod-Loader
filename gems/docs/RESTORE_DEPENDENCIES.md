# 恢复最后提交时重新检查共享依赖

0.1.69：恢复早期检查之后的目标SHA读取、恢复暂存准备或最后异步guard中，当前Store可能登记新的共享所有者或待处理依赖。新增assertRestoreDependencies，沿现有后续事务/启用MOD规则重新检查，而非把初次检查当整个操作授权。

每个待恢复条目在早期和目标SHA读取后检查；删除在最后guard返回后同步检查，再做原目标身份/链接核验和unlink。恢复覆盖通过Backup.restore新增可选第六参数beforePublish，在最后await之后、实际rename之前同步检查共享依赖，再复查暂存/目标身份与链接。前五参数兼容；同步钩子必须返回undefined，非法类型先拒绝，Promise结果拒绝并处理拒绝事件。

仅在异步beforeCommit中复查仍存在Promise完成和Backup继续提交之间的微任务窗口。测试保留原异步适配顺序，实际监测目标rename；共享记录在发布前已登记时，beforePublish拒绝提交并留下恢复待处理/applied标记，资源保持。钩子本身改变物理目标时，之后原目标封印也必须拒绝覆盖。

复现：npm run test:restore-dependencies。初始四项实际隔离文件/SQLite测试全失败，早期检查后登记共享记录导致删除/错误还原。新增记录是明确受信回调写入的合法形状事务/MOD夹具，未通过另一个Installer真实安装、没有第二个实际MOD包/游戏加载；主进程门禁当前串行化文件任务，不能当GUI并发或外部磁盘库自动同步证明。

范围：读取当前Store的已登记关系，非身份认证/防恶意本地改库或跨进程锁。不同Store的磁盘更新不会因此自动刷新当前内存，当前事务本身跨等待变化仍应单独核对。全文件/库原子、准确断电、大历史/大MOD的重复解析开销、并发和吞吐未验收。当前UI/IPC/Enhanced/正式EXE未验收，原3077不重试/绕过。
