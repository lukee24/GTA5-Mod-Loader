# 未加密 RPF 普通条目的独立副本替换

`0.1.78-dev.1` 已把现有 `replaceBinaryEntries` 后端接到桌面 RPF 浏览器。它支持选择一个普通二进制条目、预览替换前后内容，再导出新的 RPF 文件。它不安装副本，也不修改游戏里的归档。

## 使用

1. 打开“RPF 浏览器”，选择本地未加密 RPF7。
2. 在普通文件条目旁点击“替换并导出副本”，选择非空的新内容文件。
3. 核对原档、替换文件路径、原始与新内容的展开后大小和 SHA-256，以及预计输出的大小和 SHA-256。
4. 选择游戏和 GEMS 数据目录之外的新 `.rpf` 文件名。已有文件一律拒绝覆盖。
5. 只有副本落盘、完整文件回读哈希与条目核对通过，界面才显示“已导出并回读校验”。保留显示的输出路径和哈希作为文件验证证据。

取消打开、选新内容或保存不会修改原档；取消保存后可以继续使用当前预览。如果原档自打开后变化，重新打开；如果新内容自预览后变化，重新选择并预览。

## 保护与故障处理

- 原档和替换输入只读。预览与导出重新检查实际内容、文件及父目录身份。软链接、目录连接、替换输入的硬链接及不稳定读取被拒绝。
- 输出禁止覆盖原档、替换输入、任何已有文件、应用、GEMS 数据/缓存、已绑定游戏及已有导入来源。目标上级目录出现 `GTA5.exe` 或 `GTA5_Enhanced.exe` 时，即使该游戏未绑定也拒绝导出。
- 输出文件使用独占创建；其他程序在最后检查之后创建同名目标，也会得到拒绝，不能被覆盖。
- 本功能不宣称整个输出写入原子完成。如果磁盘写入中断，可能留下不完整的新副本。程序不会把它标为通过，也不会自动删除可能被其他程序改动的文件。错误中会给出保留路径；核对后另选新文件名重试。原档无需从副本恢复。
- 重建后校验所有文件条目的展开内容；落盘后校验整个副本的 SHA-256 并重新解析、提取选中条目。结构/字节校验不代表该内容可供游戏使用。

## 真实范围与限制

- 仅未加密 RPF7 的普通二进制条目；资源、目录、加密条目不能通过这个功能替换。归档含任何加密文件时，后端拒绝重建。
- 默认原档/输出不超过 512 MiB，完整重建的所有文件合计展开大小不超过 128 MiB；普通条目的实际存储长度必须能用 RPF 的 24 位字段表达。名称表及其他布局约束由后端检查，超限明确失败。
- 每次替换一个现有条目。没有新增/删除/重命名目录条目功能，没有资源格式转换和模型渲染。
- 嵌套浏览时禁用替换，必须先提取内层 RPF 并独立打开。父归档自动重写尚未完成。
- 不依赖 OpenIV。Legacy/Enhanced 资源转换及游戏内加载、操作和卸载恢复仍需各自独立验收。本功能不构成 F016 完整功能或整体项目验收通过。
