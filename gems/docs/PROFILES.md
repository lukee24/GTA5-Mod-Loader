# 配置方案：文件事务与验证边界

0.1.79 开发版本实现了原始需求第十九节要求的创建、复制、改名、切换、导入和导出。当前实现覆盖**本工具已有安装记录的普通受管文件**。方案切换会实际写入、恢复或删除本工具负责的文件，并提交对应所有权记录；保存方案名称本身不改变游戏文件。

本模块的隔离测试不能证明 GTA V 内模组加载、兼容或依赖功能正常。依赖语义、特定资源格式以及真实游戏效果仍须逐样本验证；请结合完整验收矩阵判断交付范围。

## 使用与状态

1. 绑定游戏目录，在已有受管模组中选择成员，并明确调整模组顺序。已卸载、其他游戏目录或没有完整普通安装事务的记录不能作为新选择。
2. 预览会列出启用、停用和保留的模组，所有相关目标的当前值、最终值及恢复基线。空方案表示停用当前目录的全部受管模组，不会清空 `mods` 或其他目录。
3. 同一目标可以由多个模组共享。同 SHA 仍保留独立所有权层；不同 SHA 按方案列出的顺序覆盖，最后一层生效。预览列出完整顺序和最终拥有者，执行前必须明确确认；脚本、二进制和根目录等高风险目标需要额外确认。
4. 方案固定成员标识、版本和文件内容指纹。更新模组后，旧方案明确显示版本或内容变化。用户需要重新选择以接受当前版本，然后重新预览；不会自动把旧方案迁移为新版本。
5. 导入只保存引用。缺失、停用、卸载、版本变化和属于其他目录的成员分别显示；缺失引用不会被名称相似的模组替代。跨机器导入要求目标机器已有一致的本地受管记录，不附带或下载模组文件。

导出优先使用易读缩进；若缩进会超过256 KiB，则保存紧凑JSON，保证仍在自身导入上限内。桌面保存已核验的原始导出文本，不再二次格式化。复制长名称会在120字符预算内缩短默认名称并保留“ 副本”，不会把完整Unicode代理对截成半个字符；原方案名称保持不变。

“最后提交的方案”与“当前安装记录是否匹配”分开显示。记录匹配只比较成员、版本指纹和安装顺序；它不证明磁盘未被其他程序修改。预览和执行仍会核验实际文件。

## 切换与恢复

服务先捕获方案身份、游戏目录身份、安装记录和事务摘要，以及全部涉及目标的哈希。返回给界面的计划是副本；执行使用服务私有的计划标识，不能通过修改界面数据改变目标。计划最多保留 8 个，30 分钟后或重启后需要重新预览。

切换复用安装器的 Store 排他锁和游戏目录租约。独立的底层门禁在预览、备份、每次写入、同步发布和最终提交前检查当前绑定目录、运行进程及启动保留状态。桌面集成必须在旧安装、停用、卸载、重绑和启动命令前同时检查方案待恢复账本。

任何游戏文件变更前，所有旧值、输出内容和恢复内容均需完成备份或哈希校验。文件发布前先持久保存操作意图；写入后校验最终内容。最后使用一次数据库批量提交，同时发布新的模组状态、分层安装事务、最后方案标记和完成账本。旧停用层会获得可独立恢复的原始基线，避免切换为空方案后仍依赖另一已停用模组的内容。

若中途失败或进程被终止，旧安装记录尚未改变，独立的 `profile-switch` 账本记录需要恢复的文件。恢复只接受已捕获的切换前值或本次输出值；发现外部改动、目录替换、记录变化、备份损坏或游戏仍运行时，保留文件和待处理账本。重新启动时先恢复方案，再运行普通安装器恢复；不能绕过待处理状态开始其他文件修改或游戏启动。

普通单模组逐层停用后，上层记录可能仍引用下层内容。方案仅沿更早、仍由真实受管记录引用、已经完整回滚的事务追溯到完整原始基线，再与磁盘比较；不会因为磁盘恰好等于某个历史中间层就停止追溯。无法证明完整链或链内备份损坏时，明确阻塞。缺少事务的启用记录和无法核验的最后方案标记也不能被静默遗漏或覆盖。

文件系统的逐文件发布不是操作系统级的跨文件原子操作。整次操作的一致性由持久账本、恢复流程和最终数据库原子提交实现。进程内锁不等于操作系统独占锁；外部改动通过哈希、路径身份和提交前检查发现并停止。

## 明确的容量限制

方案存储最多 200 项、合计 16 MiB；单个导入文件最多 256 KiB，每项方案最多保存 1000 个引用。**1000 个引用不是一次切换可执行 1000 个模组的承诺。**

一次最终数据库批量提交受既有 Store 的 128 项、16 MiB 上限约束，并为恢复账本与元数据留出空间。设当前启用数量为 `A`、目标方案成员数量为 `S`、两者交集为 `R`，本实现需要 `2A - R + 2S + 2` 项记录变更：

| 场景 | 最多数量，仅按记录数量计算 |
| --- | --- |
| 保留全部当前模组并重新建立显式顺序 | 42 个，合计 128 项 |
| 空目录启用已有停用记录 | 63 个，合计 128 项 |
| 停用当前全部模组 | 63 个，合计 128 项 |
| 31 个当前模组切换为另一组 32 个模组 | 合计 128 项 |

文件及记录文本大小可能使实际数量更低。每次预览会按完整方案检查容量，超限时明确阻塞；不会截断选择、偷偷拆成多个独立切换或把部分切换报为完成。还受 20000 个目标、20 GiB 内容校验预算和既有模组/安装事务读取容量约束。切换账本最多保存 1000 项、合计 32 MiB；目前不自动删除恢复历史。

## 已执行的隔离验证

- `tests/profile-lifecycle.test.ts`：创建、复制、改名、导入导出、普通和空方案切换、相同/不同 SHA 分层、顺序改变、逐层停用、完整原始基线、更新后重新选择、预览身份及恶意导入。
- `tests/profile-recovery.test.ts`：备份失败、文件写入中断、最终数据库提交失败、外部修改、进程运行门禁、损坏备份、坏账本、确认门禁、安装互斥，以及跨 Store 重启恢复。
- `tests/profile-process-recovery.test.ts`：父测试进程只强制终止自己创建的子进程，覆盖“意图已保存/尚未写文件”“首个文件已修改”“最终数据库提交前”“提交完成后”四个边界。恢复前先检查文件确实处于对应边界；提交完成后必须保留完成结果。

这些测试使用中文及空格路径、真实 SQLite 文件、真实备份及受管文件操作。模组内容为合成样本，门禁和故障由测试注入，没有写入真实 GTA V 安装目录，也没有启动游戏。实际 Electron UI、最终打包版本及独立审查的结果由总验收记录另行归档；本文件不将其提前记为通过。

## 集成接口

`new Profiles(installer, currentGamePath, baseGameGuard)` 必须使用不递归检查本模块 pending 状态的底层游戏门禁。安装器本身的门禁可额外调用 `profiles.assertWritable()`。

服务提供 `state/list/create/copy/rename/updateSelection/importProfile/exportProfile/planSwitch/execute/recover/pending/assertWritable`。导入文件先按导出的 `MAX_PROFILE_IMPORT_BYTES` 有界读取，再调用 `importProfile`；导出写入仍需采用桌面的受保护保存路径策略。`execute` 接收计划 ID 和原生确认结果。任何成功结果都保留 `gameplayVerified:false`。
