# 武器引用目录

武器中心可分析已导入资料中的明确武器配置，记录来源摘要，并导出独立的 `weapon-catalog-v1.json`。这是手动生成的时点目录，不会安装或注册 DLC，也不证明武器已在游戏中加载。

使用步骤：

1. 导入模组包或配置文件，打开“武器中心”，在“来源记录”选择该导入项并点击“解析此来源”。没有绑定游戏目录也能解析。
2. 检查武器标识、模型/槽位/弹药声明和解析问题。展开“查看来源与依赖依据”可查看来源路径、节点位置、SHA-256和字节数；搜索支持标识、哈希及来源路径，每页20条。
3. 完成受支持的安装流程后，选择对应“模组”记录并重新解析。导入记录的解析结果不自动变成安装证明；未映射到实际安装文件的武器声明不会标为文件已核验。
4. 绑定正确游戏目录后，点击“核验并导出目录”，保存到独立位置。界面返回各类文件状态的数量；注册、依赖可用性和游戏效果仍需各自验证。取消会保留已有输出。
5. 来源或目标发生变化、旧索引失效、保存位置被外部改动时，先查看明确错误并重新核对，再重试。失败会保留旧索引；更新模组后需要重新分析和导出。

“报告指纹匹配”表示派生索引对应当前来源报告，不表示已重新读取全部磁盘文件。每次导出才执行其时点文件核验；此后发生的变化不会实时更新导出文件。

“文件已核验”只表示来源确实对应当前安装事务，且核验时磁盘文件与记录一致。注册、依赖与游戏内实测单独显示；文件被复制到游戏目录仍可能没有被游戏读取。请在对应版本故事模式验证实际武器加载、外观、功能和停用恢复。

导出文件包含本机游戏目录及来源相对路径。请先检查内容再对外分享。导出供助手的独立武器目录读取；它与车辆 `catalog.json` 分开，内容不是实时同步。应用不会因为目录导出而自动解除依赖、兼容性或游戏注册限制。

支持解析 UTF-8 `.meta` 中 `CWeaponInfoBlob/Infos/Item/Infos/Item`、`type="CWeaponInfo"` 的明确 `Name`，以及同一项的模型、槽位、弹药和组件引用；不会根据文件名猜测武器。`gems.mod.json` 可声明版本化 `weaponReferences`，但声明不等于依赖已满足或资产有效。RPF 内配置当前仍待解析。

分析保留旧报告和数据库格式，派生索引单独存储。来源被修改、记录损坏、配置冲突或超出容量时停止操作并保留旧索引。导出前后会重核来源、索引、安装账本、当前磁盘文件和实际游戏根；保存对话框期间发生变化会要求重新预览。

目录最多2000条/2MiB；来源配置总量最多2000文件/32MiB，单XML最多4MiB，清单最多1MiB；安装文件核验最多20000项/2GiB，并检查60秒预算。超过限制会明确失败，不会生成被截断的成功目录。同名或32位hash冲突不能自动判断哪个模组优先，整份导出会拒绝。

本版本的目录验证与自动化测试不代替真实游戏验证。武器功能完整验收、DLC 注册、武器转换及模型/纹理/声音/动画兼容性仍以项目验收清单和实际游戏证据为准。
