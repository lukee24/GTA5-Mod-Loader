## 判定规则

- 用户再次明确：原需求每项功能必须实际可用并逐项测试后，才算可销售完整版本。禁用、占位、仅有源码/CLI或仅静态测试不能替代最终可用功能；每项应覆盖正常、失败、边界和所需真实游戏场景。销售网站VIP/账号方式不改变此门槛，不把测试总数当完整功能覆盖率。
- 每项结论绑定软件版本、实际发行文件 SHA-256、测试环境、操作步骤、预期与实际结果、日志或截图。证据标明隔离测试、桌面实测或真实故事模式测试。
- 状态只有“通过”“未通过”“未验证”“有依据的不适用”。未验证不能算通过；不适用必须说明理由，不能用于排除已承诺的核心功能。
- “可以发布”要求下面的质量门槛全部通过，且该版本宣传的每项功能均通过相应验收。“完整需求已完成”还要求原需求的功能清单全部有对应证据。两种结论分别记录。
- 未实现功能在程序、帮助和对外说明中明确禁用并解释原因；标注缺失不会自动满足原功能需求。不以按钮数量、版本号或测试数量认定完成。
- 已确认的严重安全、数据丢失、不可恢复损坏、关键流程中断和错误成功提示必须修复并回归。其他遗留问题记录影响、复现步骤及处理决定，不能隐去。
