0.1.31新增“车辆中心 → 配置副本历史”，可在桌面查找本地报告并单项核验固定目录文件/哈希/修改重建，不必只去数据目录。结果区分未核验/失败/一致，刷新/重启清除；不作为来源真实性或游戏效果证明，详见HANDLING_HISTORY.md。

当前桌面已接入真实本地XML读入、多模型选择、已有字段编辑、修改预览和独立副本保存；底层与开发CLI继续保留。安装事务、加密RPF配置编辑、音效和Enhanced实机效果仍未接入。不能把副本保存标成游戏车辆参数已经生效。

普通用户操作：打开桌面开发版，进入“车辆中心 → 车辆参数编辑”，选择UTF-8 handling.meta或XML，选择文档中的实际模型，修改数值并检查预览，点击“保存独立副本”。输出在本地数据目录的handling-edits/随机目录，包含原文快照、修改副本和报告；可通过“设置 → 打开数据目录”查看。无需运行CLI或自行安装开发工具。游戏文件不会被写入，输入配置不会覆盖。

未保存修改时禁止切换模型/重新载入，可放弃草稿；成功保存后可切换，重复保存相同清单被界面阻止。关闭会丢弃未保存的输入；已发出的选择/副本操作可能继续，迟到结果不影响新编辑窗口。损坏或不受支持的输入、保存错误在当前窗口显示，可在修正后重试。成功副本重启后仍在，文档会话不持久化；重新打开须重新选择文件，不用旧ID操作。

后端仅保存用户选择文件的一个有界只读快照，渲染器拿到实际模型/值、文件名、SHA和随机会话ID，不接收任意输出路径或XML。文件最多4MiB，句柄读取前后核对身份、大小和时间，拒绝硬链接/符号链接及读取中变化。保存基于载入时快照；输入后来变化不会被再读或覆盖。最终本地竞态、断电和大文件性能仍待独立验证。

输入为UTF-8普通XML，根节点CHandlingDataMgr，HandlingData直接包含基础CHandlingData项目。读取实际handlingName，只修改所选项目中已经存在的字段；不会猜车辆生成名、增加缺失参数或覆盖输入文件。空/重复/歧义名称、不合法数值、重复修改、实体/DTD/CDATA、其他编码声明、容量/深度或节点超限均拒绝。

支持20个字段：质量参数、驱动力系数、驱动惯性、最高速度相关配置值、制动/手刹、转向、抓地、悬挂力度/阻尼/上下限/高度/前后分配、驱动分配、挡位和重心三轴。全部以原始XML配置值读取；单位与物理换算未验收，不把驱动力或最高速度字段称为精确马力、精确极速。

编辑依据解析后的项目、字段及其源码位置，仅替换已定位数值属性；其他作者字段、子配置、注释、原有引号/换行和UTF-8 BOM保持。输出重新解析并核对数值。独立导出目录含original.meta、handling.meta和report.json，记录实际前后SHA、修改值、模型名和未安装状态；失败清理本次已创建文件，原文件不改，先前导出保留。目录/文件检查不是原生句柄锁，断电与极端本地并发仍需验证。

开发命令（在gems目录）：

```text
npm run handling -- read C:/mods/handling.meta
npm run handling -- edit C:/mods/handling.meta 模型名 C:/mods/changes.json
```

changes.json例：

```json
[{"field":"fInitialDriveForce","value":0.3},{"field":"vecCentreOfMassOffset","axis":"z","value":-0.2}]
```

例子仅演示输入结构，不是调校建议。CLI输出固定为本工程artifacts/handling-edits下的新UUID目录，不写游戏；该目录排除源码归档，避免分发用户/作者配置。CLI仅供开发验证，桌面已有对应副本功能。
