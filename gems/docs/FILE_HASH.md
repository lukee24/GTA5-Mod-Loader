# 公共文件SHA校验

当前0.1.54，R59/P2。packages/core/security.ts保持hashFile与hashOrNull公开接口，扫描、安装/目标检查、备份及快照恢复继续实际使用。新功能只核验本地文件，不执行脚本、不替代授权/兼容验证。

hashFile先只读核对各层路径无符号链接或junction，目标为普通文件且首读大小最多20GiB。捕获文件身份、长度、纳秒修改/变更时间和链接计数，打开固定fd后再次核对。按最初长度以64KiB异步分块读取，短读循环补完，不追逐追加后的EOF；实际空文件有正确SHA。提前EOF、异常长度、读取期间观察到的大小/身份/路径变化拒绝，不给出成功SHA。所有路径由单一finally关闭fd，原始IO错误保留；不再用既销毁流又手动关闭的重复所有权。

hashOrNull只将最初不存在视为null。读取开始后消失明确报告变化；不能用中途文件丢失证明原先没有文件。普通硬链接仅只读允许，未修改其他模块的独立文件策略；变化中的链接计数也检查。

不保证OS锁、原子时间点、同长度且无可见元数据变化的检测或作者真实性；没有做第二遍完整内容读取。其他报告预期SHA、备份临时副本与写前守卫仍有效，不能取消它们。64KiB为每次调用缓冲上限，不是整个进程峰值/并发保证；大文件吞吐、取消、IO超时、持续写者和真实20GiB压力仍待验收。

验证命令：npm run test:file-hash。新增10项，初始原流3项1通过/2失败，保留file-hash-initial-failure.log；修正开发时重复关句柄EBADF与一处库名测试错误，日志保留。定向32、核心586和构建通过。实际文件追加/删除/路径替换/截断、同长度改写并主动设置时间戳、短读/EOF、IO错误/fd已关、普通目录/junction/硬链接只读、20GiB虚拟元数据预检、Backup与完整SQLite/扫描/预览/安装/停用链分别测试。20GiB未实际分配；接口短读/错误不是坏盘实测，空guard不是Game版本门禁；原Installer多数变化缓存已会因预期SHA不符而拒绝，未冒称之前任意变化可安装。
