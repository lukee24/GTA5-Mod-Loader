## 安全复现与修复建议

### R34 / P2：超时误取消与原因遮蔽（0.1.26）

位置：Downloads.run总时限定时与pump.catch。原定时controller.abort(Error)，catch仅根据signal.aborted写已取消；IncomingMessage的ABORT_ERR可能隐藏具体超时原因。超时信号已触发但流尚未结束时cancel还能写用户取消。不能据此确认游戏文件损坏，主要是状态、原因与失败处理契约错误。

复现：npm run test:download-timeout。本进程只将生产30分钟回调调度改40ms，真实本地流收到generic ABORT_ERR。核对失败/中文时限/partial删除、后包真实ZIP扫描、失败SQL触发器拒绝时停队列、超时后不能改取消、用户先取消保持首因、真实SQLite重开。原8项合计7失败（含R35），日志保留；不修改系统时钟、实际网站或游戏平台。

修复建议与实现：Task区分timedOut，回调仅在未中止时标记并取消；catch保留原超时原因，超时后取消明确拒绝；正常后包继续、关键保存失败仍停。附加清理/socket错误同时显示，不能只留timeout；本轮最初修复遮蔽EACCES已被补测复现修正，保留失败证据。通用ABORT_ERR不增加无意义英文替代说明。生产仍30分钟，关闭/服务停止的细分类、续传/自动重试未覆盖。

### R35 / P2：合法摘要大小写与输入类型（0.1.26）

位置：Downloads.add接受大小写不敏感的64位hex，Task.expectedHash未经规范化，与crypto.digest('hex')小写直接比较；大写/混合合法作者值失败。GitHub parseReleases已有toLowerCase，故此缺陷主要暴露于后端输入契约，不把所有当前公开GitHub包描述为受影响。非字符串对象可被正则隐式转换，也必须保存前拒绝。

修复：摘要先明确string|null和hex格式，再统一小写；不降低真实SHA校验。实际ZIP字节/扫描/作者比对状态核验，大写、混合大小写成功；undefined/数字/对象在保存和网络前拒绝，错误SHA原测试仍失败阻止导入。首个非法值测试因默认参数改变输入失败已修正，不掩饰为产品问题。最终新增10项、核心311、构建与实际Electron离线数据/报告/重启原生核对，见TEST_REPORT。

### R33 / P2：抓取规则误匹配与正则回溯（0.1.25）

位置：catalog.ts原robotsAllows与规则读取。空Disallow不加入rules导致下一User-Agent误并组；对子串产品选择、仅按pathname、不规范化编码、以锚定符计算长度，产生错误允许/拒绝。无可解析结构的纯文本也默认放行并保存一小时，站点修复后手动重试仍用坏缓存。规则中的多个*被拼成.*，同步RegExp存在指数回溯；需要服务端提供复杂规则或相应响应变化，不是已确认任意远程执行/文件破坏。

复现：npm run test:robots。13项原有路径中12失败，原规则/新边界详情在初始日志；28个*a和无法匹配的末尾字符在自有子进程2500ms超时，父测试只终止该夹具。另有本地流规则MIME/修复重试测试；不能把子进程终止说成产品已具备主进程卡顿自动恢复。

建议与实现：独立robots.ts记录分组开始规则状态、明确实际产品标识、编码与查询路径；动态可达位置匹配替代不可信正则，记录容量/路径/总计算预算。512KiB文档容量，纯文本/UTF8检查、已知无效语法拒绝，验证成功才缓存，失败不请求分类页。稳定标识抽为client-identity.ts，未改变实际HTTP身份。参考[RFC9309](https://www.rfc-editor.org/rfc/rfc9309.html)的分组和匹配定义，属于自主实现；异常拒绝更严格、扩展与完整协议兼容未终验，不把robots当商业授权。

验证：14项/核心301、构建和真实Electron/IPC/HTTPS品牌目录成功。项目4096、模式4096、地址8192、计算预算800万，超限停止而不是按部分结果允许；未完成所有站点规则样本或整机压力/渗透验收。原商业/游戏阻碍保留，具体证据见TEST_REPORT。

## 0.1.8 追加：R14 / P1 启动环境削弱 HTTPS 验证

位置：packages/marketplace/network.ts 的资产/API 请求与固定公共 DNS 请求。旧版本依赖 Node 默认设置；当启动环境含 NODE_TLS_REJECT_UNAUTHORIZED=0 时，实际 TLS 客户端接受未被信任的证书，可能失去下载及元数据来源身份保护。此条件需要不安全启动环境，不把默认正常环境描述成无证书验证，也没有远程代码执行实测结论。

复现：npx tsx --test tests/tls-policy.test.ts。父进程生成只在内存存在的 RSA/SHA-256 测试证书，绑定 127.0.0.1 随机端口；独立测试子进程继承故障环境，并将生产请求的路由映射到该 TLS 服务器。生产域名与公网检查仍执行，真实 TLS 完成验证。初始两项 accepted=true，失败日志保留；修复后 accepted=false，HTTP 请求数为 0。测试路由注入只在独立进程，不是产品对私网的允许机制。最终回归使用默认 HTTPS Agent。

修复：两个请求显式 rejectUnauthorized=true，最低 TLS 1.2；保留默认主机名与 CA 验证。没有导入信任、内置私钥、自签名发行或更改系统策略。Node 的[环境变量文档](https://nodejs.org/api/cli.html#node_tls_reject_unauthorizedvalue)说明该变量会削弱验证，[TLS 连接文档](https://nodejs.org/api/tls.html#tlsconnectoptions-callback)定义验证选项；本机 Node 与 Electron 的真实握手证据补充这些接口说明。

验收：核心 157/157；npm run test:tls-policy-ui 验证真实 Electron 在 HTTP 读取前拒绝测试证书，显示中文错误且不保存假目录；正常公网 API 元数据读取仍通过。原站浏览器 Chromium、网站窗口退出和全部网络攻击路径仍待独立审查。初始本地夹具采用独立新 Agent，随后定向/UI 扩展为默认 Agent，验证没有依赖特殊 Agent 才通过。详见 TEST_REPORT.md。
