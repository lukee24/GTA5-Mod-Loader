# 人物引用、收藏与目录

人物中心从已保存的真实来源解析模型声明，保存此来源版本的收藏和自定义分类，并在导出时核对安装事务、对应文件和当前磁盘。文件显示“已核验”仍不能证明人物注册、模型加载或游戏效果正常。

## 操作

1. 导入人物配置或模组包，在人物中心选择对应来源并点“解析此来源”。损坏来源不会覆盖已有索引；只有模型、纹理或服装文件时，不根据文件名猜测人物标识。
2. 查看模型名、hash、配置中的`Pedtype`、依赖引用和来源SHA。可搜索、分页，并编辑军事、警察、平民、动物等自定义分类。自定义分类不改变配置事实或生成资格。
3. 收藏属于`来源类型+来源ID+引用ID`。导入来源与安装记录分别保存；安装、更新或内容变化不会把旧收藏自动移给新引用。损坏偏好保留并报错，不以默认false冒充已保存结果。
4. 绑定Enhanced目录后，点“核验并导出目录”，保存到独立位置。取消、来源/数据库/安装文件变化或输出目的地被外部替换都会拒绝当前写入，保留已有输出。

导出文件为`ped-catalog-v1.json`，包含本机游戏目录和来源文件路径。它不注册DLC、不安装人物、不建立实时同步，也不向车辆或武器目录添加字段。游戏助手读取及实际人物生成仍需相应版本的真实故事模式测试。

## 可解析来源

XML仅从`CPedModelInfo__InitDataList/InitDatas/Item/Name`读取明确名称，并读取同一节点的`Pedtype`和配饰、动作、表情、生物元数据、移动动作集引用。禁止DTD/实体、过深结构、重复或无效节点。当前模型token限制为ASCII字母开头、最多64位字母/数字/下划线；路径可含中文和空格。YMT、RPF、YDD等资源保留未解析说明，不伪造模型或完整服装资料。

作者也可在包根`gems.mod.json`提供独立声明：

```json
{
  "format": 1,
  "files": [{"source": "peds.meta", "target": "mods/GEMS-example/peds.meta"}],
  "pedReferences": {
    "schemaVersion": 1,
    "entries": [
      {
        "modelName": "gems_example_ped",
        "kind": "addon",
        "sourceFiles": ["peds.meta"],
        "dependencies": [{"kind": "runtime", "identifier": "作者声明的依赖"}],
        "thumbnail": "portraits/example.png"
      }
    ]
  }
}
```

示例包需实际包含`peds.meta`和`portraits/example.png`；没有图片时删去可选`thumbnail`字段。根级非空`files`是现有扫描器要求的明确文件映射；上述映射只说明把文件放到哪里，不会把它注册为游戏人物，也不执行RPF写入或Add-On注册。

`kind`支持`addon`、`npc-replace`、`protagonist-replace`、`unknown`，均是声明。`sourceFiles`必须明确指向本包真实文件；缺失、重复、越界或大小写别名会拒绝。显式依赖只支持`file`、`dlc`、`runtime`。这些字段不会解除安装或兼容性阻塞。

## 作者提供的缩略图

可选`thumbnail`只接受本包独立普通文件。当前支持PNG/JPEG，最多512KiB，单边最多2048像素，总像素最多4Mi。不接受URL、SVG、任意外部路径或根据模型名自动选图。图片本身属于作者提供的预览，不是GEMS渲染出的模型，不证明与游戏中外观一致。

PNG限定非交错8-bit图，核心检查块结构、CRC、有界解压长度和行过滤器；桌面额外实际解码。JPEG分析阶段只绑定头尺寸与来源；实际读取必须由调用方提供真实图像解码器。桌面使用Electron内置解码，空结果、解码错误或尺寸不符时不返回图像。纯Node没有JPEG解码器时会明确拒绝；Node测试的假decoder只检查接口准入，不能证明真实JPEG可用。缩略图不进入游戏目录包，桥接字段保持不变。

本版主执行的实际Electron检查见`artifacts/0.1.85-ped-thumbnail-working-1.json`：自制40×30像素PNG/JPEG经真实扫描、来源核验、Electron及Chromium解码显示；合法头但无实际像素的JPEG被拒绝。该证据属于主执行的桌面测试，不属于纯Node模块测试，也不是游戏模型截图。

每次读取核对扫描SHA、字节数、来源根、链接和文件身份；缓存描述不能授予读取任意文件的权限。缺图显示缺图；损坏图报错，不用合成图片替代。

## 文件状态与边界

目录分别记录`verified`、`disabled`、`uninstalled`、`pending`、`missing`、`changed`、`shadowed`、`unverified`。只有相关引用的源文件确实映射到本事务已应用目标，且最高所有权及当前磁盘hash都匹配，才可能标记文件已核验。只安装同一MOD的辅助INI不能证明人物资源已安装。

导出还会重解析来源事实，复核声明的二进制`sourceFiles`及缩略图的真实源SHA/身份，并在保存对话框返回后再次验证快照。注册和依赖可用性保持未知或仅声明状态；桌面收藏与游戏本地收藏没有双向同步。

当前上限为2000引用/2MiB目录，单XML4MiB，配置文本来源最多2000文件/32MiB。声明的二进制资产及缩略图使用独立的最多20000文件/2GiB来源预算，不占用配置文本额度；资产通过固定64KiB缓冲区流式核验，36MiB合成来源和对应安装目标已验证。安装目标另有20000项/2GiB预算，来源与目标分别计费；准备和保存前复核会重复核验。每轮采用单调时钟的60秒合作式检查，不能中断已开始的单次哈希调用。超过限制明确停止，不截断成看似完整目录。

Add-On注册、资源转换、加密RPF写入、完整服装/面部编辑、模型3D预览和真实游戏效果仍未完成。本模块的合成文件测试及目录协议测试不代表这些能力通过。
