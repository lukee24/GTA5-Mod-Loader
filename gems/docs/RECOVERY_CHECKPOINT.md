0.1.70：RecoveryCheckpoint记录当前Store中本事务的最近一次已保存语义快照。在guard等待、目标SHA读取、覆盖beforePublish/删除前，以及每次事务保存前检查当前记录。缺失、坏JSON/结构、状态、错误、身份或操作清单变化时停止恢复并保留最新记录，不复活删除的事务，也不拿内存副本覆盖损坏证据。

save先比较，再规范化JSON和既有形状准入，实际Store.put成功后才推进检查点；自己的状态/applied/error保存是合法推进。错误处理也先核对检查点，发现当前事务变化时抛中文错误，不再保存旧恢复错误。JSON键顺序变化不算语义变化，undefined规范化符合实际数据库JSON。

复现：npm run test:recovery-checkpoint。原三项实际隔离Scanner/SQLite/小ini，guard中把applied改false/增加新审核文本，原仍删除并覆盖；删除事务被旧恢复重新创建；坏JSON被内存旧图自动改回合法记录。变更由明确受信回调直接操作当前Store，不是GUI/跨进程或游戏加载实测。

发现变化前可能已有部分文件恢复。例如进度回调在applied=false已保存后更新审核记录，完成状态保存被拒绝，目标已经删除；最新待处理记录保持，不能说文件全部未改。应核对当前事务与文件，再用最新记录重试。原份备份、文件身份、共享依赖、末段guard与同Store互斥继续执行。

这是当前Store内存账本的乐观检查，不是磁盘数据库自动同步、版本号/ABA检测、防恶意本地改库、跨进程锁或全文件/库原子。其他Store共同写游戏目录、安装执行阶段自己的事务变化、极限记录错误增长容量、大历史的重复解析/内存峰值和准确断电仍需独立审查。当前UI/IPC/Enhanced/最终EXE未验收，原3077不重试/绕过。
