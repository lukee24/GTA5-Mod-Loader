# 模组版本更新

此功能更新 GEMS 已启用模组的普通文件安装记录。它使用真实导入文件、备份、SHA-256 和事务记录；不会自动推断包的作者身份，也不会把文件更新结果等同于 GTA V 加载成功。

## 使用方法

1. 退出 GTA V，绑定该模组原来安装的游戏目录。
2. 在“导入模组”导入新版本，核对作者说明、来源及文件目标。
3. 在“模组中心”找到当前已启用记录，点击“更新版本”。
4. 选择已导入的新版本，点击“检查更新差异”。检查每个新增或替换目标，以及每个旧版独有文件的恢复结果。
5. 无阻塞项时点击“备份并更新模组”，在确认框核对模组身份、改动数量和脚本风险。
6. 文件更新完成后，仍须进入对应版本 GTA V 故事模式确认模块加载、实际功能和退出后的日志。应用中的“游戏内待测试”不会自动变为通过。

已停用记录需要先按原有预览流程启用后才能更新。快照恢复记录不能作为更新对象。未实现的转换、DLC 注册、加密 RPF 编辑等能力不会因选择更新而绕过限制。

## 文件和恢复行为

- 新版仍包含的目标写入新版文件；新版不再包含的目标恢复为首次安装前的文件。首次安装时不存在的目标才会删除。
- 在任何游戏文件修改之前，核验旧版目标的当前哈希和所有权，核验原始备份，并完整备份本次所需的现有文件和新文件。备份失败时不进入修改阶段。
- 更新失败会按事务清单恢复旧版。若发现外部编辑、文件占用或损坏备份阻止恢复，旧版记录保留，并显示“恢复待处理”。必须核对并解决阻塞后在“备份与恢复”继续处理；此时不能把旧版或新版认定为可用。
- 更新成功后，在一个数据库提交中转交新版所有权和原始恢复基线。旧版事务保留，标注已被更新事务替换；新版停用或卸载恢复首次安装前的文件，而非把旧版重新留在游戏目录。
- 新版目标属于另一启用模组时阻止更新。目标内容即使相同，也不能据此取得另一模组的所有权。
- 停用、重新启用和卸载继续使用现有哈希、目标边界、进程检查和外部修改保护。未修改的用户文件、其他模组及配置不会被清空。

新版本记录使用 `operation: "update"`，删除操作的 `after` 为 `null`。旧版 GEMS 无法识别该记录时会停止准入，不应使用旧版程序打开这份验收数据。

## 本轮证据与边界

- `tests/mod-update.test.ts`：正常更新、连续更新、旧版独有文件恢复与删除、原始基线、源和目标变化、其他模组所有权、备份故障、写入故障、数据库提交故障、待处理恢复、重启恢复、外部编辑保护。
- `tests/mod-update-ui.mjs`：实际 Electron 界面与 IPC，在中文及空格路径中完成预览、取消、外部修改拒绝、更新、停用、重新启用和卸载。只替换原生文件选择与确认框的返回值；未替换应用的游戏守卫。
- `artifacts/mod-update-regression.txt`：更新及相关生命周期、恢复测试的执行记录。
- `artifacts/mod-update-ui-current.json` 与 `artifacts/ui/mod-update-preview-dark.png`：桌面测试范围与截图。
- `tests/update-process-recovery.test.ts` 与 `artifacts/update-process-recovery.txt`：在部分写入、旧文件删除、最终数据库提交前和提交后实际终止更新子进程，再打开数据库。前三种恢复旧版；已提交更新保持新版；四种随后卸载均恢复原用户文件并保留无关模组。
- `tests/mod-update-review.test.ts`：修复等价目录带尾部分隔符时漏检待处理事务的问题；同一目录阻塞，不同目录保持独立。

上述文件测试使用本项目生成的 INI 样本和合成 PE/RPF 头目录，不是 GTA V 游戏运行。真实模组加载、功能使用和退出后恢复验收仍待实测，不能由这些结果替代。
