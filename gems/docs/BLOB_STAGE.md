Backup.put不是简单copy后报成功。先核对源实际SHA/长度，再为同目录独立普通暂存捕获全部父目录及inode身份；复制后核验、刷新、再次核验，提交前同步复核。通过独占硬链接创建内容哈希名称，已有名称不会被替换；并发赢家必须实际验证，损坏或变化拒绝且保持原对象。

新发布阶段有tmp与blob两个名称，只有二者同本次inode、同普通父目录且nlink=2时才解除tmp，随后核验实际最终blob。失败清理不依名称猜所有权；替换、外移、未知多链接与清理失败保留，不伪称保存成功。已有blob的只读硬链接策略保持原行为，不能由此擅自删除其他名称。

npm run test:blob-stage运行10项新增和相关87项回归。原3项失败证据、每个隔离实际文件断言见tests/blob-stage.test.ts与artifacts/blob-stage-initial-failure.log；最终97/97，完整627/627和构建日志见测试报告。Installer集成使用隔离noop guard，未接触真实游戏。

当前只在本机NTFS验证。备份盘不支持硬链接/权限不足时明确失败，不退回可能覆盖已有目标的rename；ENOTSUP为函数故障夹具，不能称已实测其他设备。发布后外部损坏对象保留，后续验证仍拒绝，不自动覆盖修复。

临时文件在copy失败或捕获所有权前可能残留；link后中断可能留两个名称。本轮没有准确该点进程中断或断电验收、目录持久性保证，也没有安全清理维护工具。末段检查不是OS锁/目录fd提交，仍有外部写者与目录换址竞态；同长度无可见元数据变化、取消/超时、大MOD/峰值与跨文件系统需继续实测。UI/IPC/Enhanced/可信发行仍按各自证据验收，测试数量不能替代全功能商用验收。
