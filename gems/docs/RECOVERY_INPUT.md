# 恢复输入与持久化操作清单绑定

0.1.66：恢复入口在任何等待之前复制并验证请求，再与实际保存的事务逐字段比较，包括状态、错误、全部目标、前后SHA和applied标记。只执行数据库读取的私有副本；输入不被回写，调用者应使用返回Transaction核对结果。过期或伪造请求在guard和首次保存之前中文拒绝。

安装失败可能留下尚未保存的内存条目/应用标记。失败回滚重新读取实际事务，不用未提交的内存图冒充恢复权限。自动recover改为使用返回结果校正MOD状态和记录日志。现有目标、共享所有权、哈希、备份、末段守卫和文件身份检查继续执行。

复现和回归：npm run test:recovery-input。原四项实际隔离文件测试全失败，包括无归属文件被删除、覆盖原文的before改null被删除、applied改false却报告已回滚，以及guard期间换目标造成无归属删除。不是当前桌面GUI攻击证明：main没有向renderer提供任意事务恢复接口。

接口变化：restoreTransaction不再修改传入对象。既有两个commit-guard测试改用返回结果，并同时核对真实数据库待处理状态和原请求未变；保护目标的断言保留。冻结请求可正常恢复，旧请求重放明确拒绝，重新读取已回滚记录可幂等恢复。

限制：数据库是本地恢复权限来源，未新增签名/防恶意本地数据库篡改。复制前整体预算/复杂图、多个Installer实例或直接API并发、跨等待数据库语义变更仍需独立审查；私有输入不等于物理文件锁、全文件与库原子或硬件断电验收。当前Electron被原Device Guard 3077阻止，不重试/绕过；当前UI、IPC、Enhanced和最终EXE未验收。

验证：新增9项，定向89/89、核心699/699/0跳过、构建通过。首次39项两处旧原参数回写断言失败已记录并按返回结果契约修正，真实文件保护要求未降低。完整证据见TEST_REPORT.md和artifacts/recovery-input-current.json。
