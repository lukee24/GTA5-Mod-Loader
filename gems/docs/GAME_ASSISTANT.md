# GTA5模组加载器：实验性游戏助手

游戏助手是实验性 x64 `.NET Framework 4.8` 脚本。**旧 DLL 已完成真实故事模式加载、F5 中文菜单及部分车辆操作；0.1.86 速度修复 DLL 的游戏复测未完成，桌面自动安装仍禁用。** 安装 GTA5模组加载器桌面软件不会部署助手；现有程序及原生模块内部仍沿用旧名GEMS。本次桌面候选为0.1.86-dev.1；原生DLL保留构建时0.1.85-dev.1程序集身份，固定 SHA-256 见[本版记录](../../docs/DEVELOPMENT_ACCEPTANCE_0.1.86.md)。较早记录仅证明各自版本的软件检查，`capabilities.json`的not-tested表示最终完整游戏门槛仍未通过。

## 后端来源与支持范围

编译采用作者 Chiheb-Bacha 的 [ScriptHookVDotNet Enhanced 官方仓库](https://github.com/Chiheb-Bacha/ScriptHookVDotNetEnhanced)发布的 [v1.1.0.6](https://github.com/Chiheb-Bacha/ScriptHookVDotNetEnhanced/releases/tag/v1.1.0.6)，不是 Rockstar 官方接口。作者说明该运行时支持 Legacy 与 Enhanced 共用 API；这项声明不等于本项目已在相应游戏构建上验证。

开发机固定SDK材料位于`native/game-assistant/third_party/shvdne`，取得与摘要核对步骤见[BUILDING.md](../native/game-assistant/BUILDING.md)。公开源码ZIP不含运行二进制或游戏资产。SHVDNE主许可证为zlib，第三方声明保留各自条款。本项目编译只引用`ScriptHookVDotNet3.dll`，不复制ASI/API DLL到插件产物。不内置、自动安装或重新分发Alexander Blade的Script Hook V；精确版本支持应从[作者网站](http://www.dev-c.com/gtav/scripthookv/)核对，再取得实际游戏证据。

运行时还需要 SHVDNE 作者要求的 `.NET Framework ≥ 4.8` 和 x64 Visual C++ 运行时。只能使用同一 SHVDNE release 包中的 ASI、API DLL 及其配套组件，不能混用不同版本。

菜单通过Windows GDI生成字形纹理，再由SHVDNE绘制，不是HTML浮窗，**没有动态模糊**。当前采用最多2048字形预算与8行滚动视口，超预算或不可读字形不能作为操作确认；早期128张整页纹理的描述已不适用。离线GDI图片不能替代真实游戏分辨率、缩放与输入验证。默认F5与Alt+G打开同一菜单，可在“输入与映射”修改；手柄打开组合默认未绑定，独立快捷中心尚未实现。

菜单打开时会请求当帧控制抑制，不能同时用相同输入驾驶或开火；关闭菜单后观察效果。暂停、失焦或角色资格变化清旧预览，恢复后须释放并重新按键。映射录入、保存及损坏记录恢复的步骤见Stage4；其他MOD的输入冲突仍为未知。

### 0.1.84武器状态与恢复合同

当前源码按以下合同处理，软件验证范围以本版记录为准。清除针对当前角色原有及MOD武器，是二次确认的一次性命令；审计不等于完整库存备份，可能随游戏保存。结果只读核对，残留或超时不自行再清除。

组件安装、活动和涂装分别记录，未知字段不当作0。条件恢复限于同一连续会话及本次操作后观察值仍匹配；同值外部接管不能证明归属，组件任意新色范围尚未确认。多步恢复中途失败必须保留已经发生的修改，不能宣称完整恢复。

库存必要观察与所选武器详情分开读取。组件全局定义最多1024项、单武器组件最多512项；超限整体标未知。每次组件详情共享75ms合作式预算，超时不留下可用的部分组件列表。同步接口本身不能被中断，多次确认/复核也会重复读取，因此75ms不是整次操作或游戏帧耗时保证。菜单提供具体拒绝原因；详情受限时仍可按角色与库存条件处理明确清除请求。

无限弹药分共享弹药池和全角色弹匣两种范围，开启与强制关闭是明确请求。SDK缺少可用状态getter，上次请求/调用返回不代表当前flag已确认；关闭不是还原未知原值。隐藏菜单、失焦、暂停或卸载脚本不应被描述为效果已关闭；取消只撤销未提交预览，已提交效果须另行明确关闭并实际射击/换弹观察。无失败自动重试、隐式关闭或重启重放。

## 本地只读桥接协议

车辆固定读取位置为`%LOCALAPPDATA%\GEMS\bridge\catalog.json`，独立武器目录为同目录的`weapon-catalog-v1.json`。桌面导出独立文件，不自动部署、不注册DLC、不建立实时同步。不能把未注册DLC标作可用。目录应保留当前用户访问边界，不放在多人可写公共目录。车辆准备状态和上限见[车辆契约](BRIDGE_CATALOG.md)，武器来源/文件核验与导出见[武器说明](WEAPON_CATALOG.md)。人物和房产导出仍未实现。

```json
{
  "schemaVersion": 1,
  "revision": "2026-10-12T00:00:00Z",
  "vehicles": [
    {
      "id": "mod-id",
      "name": "奔驰 S500 Coupe",
      "brand": "奔驰",
      "spawnName": "s500",
      "dlcName": "s500",
      "enabled": false,
      "installState": "prepared",
      "requiresGameRestart": true
    }
  ]
}
```

以上是协议示例，不是内置车辆或已安装记录。脚本只展示 `enabled: true` 且 `installState: "installed"` 的项。这里 `installed` 只表示桌面静态安装及所需 DLC 注册完成，绝不表示游戏加载成功。没有真实 RPF 注册后端时，保持 `prepared` / `files-written` 并设为 `enabled: false`。目录本身不触发模型生成；必须由用户在故事模式菜单中选择，并通过游戏实际模型检查。

脚本每 5 秒重新读取目录，修订号变化才更新。发布者应先写同目录临时文件、刷新并原子替换 `catalog.json`，每次更改使用新修订号；禁止写一半目录后让读者读取。上限为 2 MiB、2000 项；`spawnName` 只允许 1–64 个 ASCII 字母、数字或下划线；拒绝大小写重复名称、缺失必填字段、未知协议版本以及路径祖先的符号链接/联接点。

该协议没有网络端口、通用命令、脚本执行、DLL 载入或任意文件目标。文件可被同用户编辑，因此它是受限本地配置同步，不是抵御已控制该用户账户的安全边界。新 DLC 需重启游戏；菜单明确提示，不承诺热加载。

生成前检查模型类型、有效性和加载状态，最多等待5秒；随后检查附近地面与车辆/人物。空间不足或模型不可用会拒绝。创建后验证实体存在并记录；符合会话条件的实体登记为本实例临时车辆，最多16项。世界页清理限于10米内、无人占用且身份/状态仍符合条件的记录；创建后失去资格时不假称可管理。没有持久车库，创建对象也不证明材质、LOD、碰撞或外观通过。

## 构建与离线检查

开发机器需要 .NET SDK。请解压完整源码包，在`gems`目录执行下列命令；文中的Stage/原生工程相对链接也以完整源码目录为准。桌面安装包仅附使用文档，不含原生工程或SDK；桌面普通用户无需该开发环境。

```powershell
pwsh -NoProfile -File .\native\game-assistant\build.ps1
```

输出：`native/game-assistant/artifacts/GEMS.GameAssistant.dll` 与状态清单。构建脚本先校验固定 SDK 下载包，再编译和执行离线检查。

早期源码预览曾记录76项离线检查通过及首次符号链接特权不足；这些是历史证据，不能当作当前版本通过，联接点通过也不替代未执行符号链接用例。当前各分组的命令、结果与限制按Stage和版本报告记录。默认build脚本只执行核心组，不包含全部实际Script、端口、存储与GDI检查；单次构建不能代表整功能验收。

中文纹理检查命令：

```powershell
dotnet build .\native\game-assistant\tests\visual\VisualCheck.csproj -c Release
.\native\game-assistant\tests\visual\bin\Release\net48\VisualCheck.exe
```

生成的 `preview.png` 使用同一菜单栅格代码；已目视检查中文字体、长名称省略、8 行布局和底部提示。此 PNG 使用专门测试文字，不代表真实车辆数据库；离线纹理检查也不等于真实游戏渲染验收。

## 日志

本地日志：`%LOCALAPPDATA%\GEMS\game-assistant\assistant.log`。记录加载、目录同步、菜单操作、模型失败、实体创建和脚本退出，不上传任何数据。单文件超过 4 MiB 时保留为带时间的本地归档；当前尚未实现总归档空间清理策略。中文菜单纹理缓存保存在该目录的 `menu-cache` 子目录。异常路径只写本地日志，不在菜单中显示完整用户路径。

映射历史位于`input-mappings-v1`。武器审计目录仍名为`weapon-actions-v1`，本版追加兼容旧记录的v2内容，不清空v1历史；单条1MiB、总16MiB、2048文件，写意图前预约结果容量。记录仅是证据，不授予跨重启恢复/移除权限。本轮真实游戏已写入助手日志、菜单缓存和车辆收藏；武器审计与映射的游戏使用未验证，相关软件测试仍仅使用隔离夹具。
