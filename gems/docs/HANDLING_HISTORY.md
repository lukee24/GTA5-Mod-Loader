# 车辆配置副本历史与内容核验（0.1.31）

进入“车辆中心 → 配置副本历史”。列表读取实际handling-edits目录中的本地报告，显示模型、报告日期和报告改动数量；没有副本时不放示例。报告缺失/不受支持或目录连接会显示异常，无法确认的名称、日期、数量不猜测。

列表只做报告格式与固定路径检查，初始状态是“未核验”，不是文件内容已验证。点击“核验副本内容”后才读取原文快照和输出，核对实际SHA-256，并用原文和修改清单重建预期输出；输出额外改动、伪造修改前值、重复字段/错误轴、摘要不符或读取期间变化会拒绝。成功显示“内容核验一致”，失败显示“核验失败”和中文原因。失败不自动修复/删除文件；修正后可以重新核验。

只读取当前数据根内固定的UUID目录和report.json/original.meta/handling.meta，不采用报告指定的任意路径；报告路径声明必须与这些位置一致。目录连接、资源硬链接/符号链接、无效标识/尾部换行、超过读取上限、坏UTF8或不支持的状态拒绝。最后复核报告/原文/副本的文件身份、大小与时间，检测已经观察到的中途变化；不是OS文件锁或原生最后竞态解决方案。

保护限额：最多读取1000个目录条目（包括不受支持条目），最多展示100个副本，报告最多64KiB，原文和输出各4MiB。达到限额会说明列表不是完整历史，其他文件仍保留。列表不自动对所有XML读取/核验，没有完整历史分页/搜索、批量核验或清理。刷新与重启不保留旧的成功状态，重新核验须显式执行；结果附核验时间，之后文件仍可能改变。

这些报告是可修改的本地数据，不具备数字签名。核验只能确认当时文件与报告内部一致；同时修改原文/输出/报告使它们自洽时，不能据此证明来源、作者授权或从未被篡改。不是GEMS归属认证、恶意代码检测、车辆安装、资源转换、Enhanced兼容或游戏效果实测。当前接口不写游戏，不承担RPF/安装事务/音效功能。

证据：新增12项/core-tests-handling-history-current.log核心368/368，handling-history-current.log包括空数据、真实文件/报告只读、外部路径零读取、目录连接/硬链接、原文/输出变化、更新摘要仍存在额外改动、伪造修改前值/重复/轴、坏/缺/超大报告、UTF8/4MiB、读后报告变化、101副本/1102目录项真实限额。均隔离配置夹具，不是作者MOD/游戏验证。

handling-history-ui-current.json/log实际Electron/原IPC：从编辑器真实保存后显示历史、实际核验/哈希/文件不改、篡改拒绝、刷新清除/修正后重试、异常报告禁用、Tab/Esc/焦点恢复、深色1440/浅色1024/长路径/滚动、车库工具栏小窗与退出重启通过；原生文件选择只在测试进程注入本地夹具路径，不替换核验回复。目视截图在ui/handling-history-*.png。本轮无公网和真实游戏操作。
