# 下载文档准入与启动保护（0.1.30）

修复R36/P2：数据库文件和表结构合法，不代表每条下载JSON都可用。之前null、损坏JSON等会在启动/下载列表中抛出异常；未完成下载逐条整理还可能在后一条失败前已部分改写。现在先只读核对完整受支持范围，再一次批量提交中断整理。

SQL读取在跨入JavaScript前限制单文档64KiB、标识80字节；下载历史最多完整核对10000条、文本合计16MiB，JSON节点最多4096、深度32。超条数仅读取近期200条，任何异常或超限都会停用下载/重试，保留可展示的合法记录与全部原文档；不删库、不删除坏记录、不猜字段、不自动迁移。未完成记录超过队列上限30项也停止自动整理。正常旧格式可用，受限结构内的未知附加字段仍保留。

校验标识/文件名、状态、非负整数接收计数、声明大小、真实日历日期、HTTPS来源、摘要、关联、绝对文件路径以及可选公开发布元数据。来源不接收URL凭据/查询/片段，异常值不会被写成“正常”。失败传输可能因超限多接收一个块，真实超限计数不会被误判为文档损坏。校验不是文件存在/内容哈希/报告引用或作者来源真实性验证，也不是数据库全部文档类型的保护。

下载服务异常不会阻止首页、导入、设置与其他模块正常工作。停止服务时，旧的未完成状态标注为“历史状态”，不显示执行进度条或可用取消按钮；没有可展示记录时明确说明，不能把坏数据当成空队列。告警在下载页显示，本轮不新增持久告警或自动修复功能；修正数据后仍需重启重新核对。

启动整理使用已有writeBatch，一次提交所有受支持的未完成记录；SQL、文件或外部更改拒绝时整批保留旧状态，只停止下载组件。列表、报告关联通知、重新下载和新任务入队均经过准入，避免旁路直接解析坏JSON或先创建新任务。正在执行任务遇到新异常时会停止接收并取消网络，已有安全收尾仍可能提交该任务结果；不等同强制中断扫描或所有数据冻结。

证据：最初7项失败保存于download-admission-initial-failure.log；修复后新增12项/核心356，真实SQLite/null/损坏JSON/字段异常/深度/容量/10001历史/31项未完成/SQL拒绝、原文和文件保护通过。实际Electron5种场景，原IPC、真实文件导入、设置、退出重启及原生SQLite逐字核对异常下载文档通过；正常场景按真实结果改为中断并保留未知字段。深色1440/浅色1024已目视检查，均为隔离夹具，无网络/游戏操作。

原生并发最后校验至rename竞态、断电、256MiB数据库整体载入内存峰值、长历史性能、完整历史浏览与用户修复/清理界面仍待验收。10000/64KiB/16MiB是当前保护限额，不是已证明所有大型历史都性能正常。公网下载重试仍沿用0.1.29受限结论，没有再次请求GitHub；商业与游戏功能终验不因本修复完成。

开发复现：`npm run test:download-admission`、`npm run test:download-admission-ui`。测试只创建并清理明确的临时目录，不修改用户数据库、真实游戏文件或系统安全策略。
