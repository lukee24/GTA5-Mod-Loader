## 工程和使用

本阶段继续修改本仓库的 `gems/`，沿用 Electron、React、TypeScript、SQL.js 和实验性 C# 助手。0.1.78产物和证据单独保留。完整原需求、45节索引、65项功能及A—H场景见[验收清单](../gems/docs/ACCEPTANCE_MATRIX.md)，没有缩减交付范围。

Windows x64、Node.js 24，从 `gems/` 执行 `npm ci`、`npm test`、`npm run build`、`npm start`。配置方案的操作与限制见[使用说明](../gems/docs/PROFILES.md)，助手独立构建见[BUILDING.md](../gems/native/game-assistant/BUILDING.md)。助手尚未部署或验收，桌面自动安装保持禁用。

开发产物位于 `gems/release/`：`GEMS-0.1.79-dev.1-source.zip`、`GEMS-0.1.79-dev.1-x64-setup.exe`、`GEMS-0.1.79-dev.1-x64-portable.exe`。用安装向导安装并启动GEMS，或直接运行便携包；二者都不需要开发依赖，均为未签名开发包。遇到系统阻止时保留错误，不修改系统保护。各文件实际SHA-256见同目录`manifest.json`和`SHA256SUMS.txt`。源码不含游戏资产、第三方MOD、SDK二进制或本机私人证据。

默认数据目录为`%APPDATA%\GEMS\Studio`。卸载GEMS软件会保留该目录，不等于卸载游戏中的MOD；受管MOD须先按对应事务停用/卸载，再实际核验游戏。当前实验性助手DLL单独保留在`native/game-assistant/artifacts/`，未随桌面安装器部署进游戏。

配置方案可保存已受管普通文件模组的固定版本和顺序，复制、改名、导入、导出，并预览整组切换。空方案恢复当前受管模组的原始基线，保留未受管文件。发生外部修改或未完成恢复时，先处理账本中明确指出的问题，再通过恢复入口重试；不要删除账本、清空模组目录或重装游戏代替恢复。导入方案只带引用，不带模组文件，不能按名字自动匹配另一台机器的模组。

## 修复记录

- 方案切换与旧安装器都检查全部启用记录的事务存在性及所属模组，防止丢失同内容覆盖层的所有权。
- 损坏的活动方案标记会阻止修改；普通逐层停用后，沿完整可证明的恢复链找到原始基线，再核对当前磁盘，避免把历史中间层误认成原文件。
- 最后一项文件恢复之后、发布完成状态之前，再核验所有权和持久事务；发生变化时保留待恢复记录。
- 方案预览弹窗原来挂在页面根部，未继承主题变量。实际截图发现透明背景后，改为挂在应用容器，复测深浅主题与窄窗口。
- 首页原来只搜索包含“待处理”的文字，遗漏另一种有效恢复提示。改为依据实际恢复列表非空显示提醒；实际界面已验证待恢复时显示、全部恢复及重启后消失。
- 合法大方案因缩进导出超过自身256 KiB导入上限；现按字节预算选择缩进或紧凑输出，桌面保存该文本而不再次格式化。合法长名称默认复制超长，现保留“ 副本”后缀并安全缩短默认名称。修复前10项检查中7项失败、3项通过，日志`0.1.79-profile-export-capacity-original-fail.txt`保留；修复后10项纳入900项全量通过，实际界面5组往返通过。

车辆助手接入当前车修复、清洗、有限翻正、性能槽改装、RGB和车牌输入、引擎/无敌/车门窗/灯光/轮胎/悬挂档位/低速请求及车型收藏。只有无敌、引擎运行、内灯的可观测布尔状态按身份和最后写入值条件恢复；一次性操作有明确限制。输入后重新核对角色、车辆及停车状态，收藏采用追加记录保护原文件。所有实际车型与效果仍待游戏验收，不能把离线路径数写成16项游戏功能已通过。4类未执行项为桥接符号链接、收藏ACL拒写、收藏目录及文件符号链接。

最早几项独立审阅失败记录仅存在本轮工具输出，没有另存原始日志，不把后写说明冒充失败日志。已有的界面测试定位器失败日志、截图及后续复测均保留。
