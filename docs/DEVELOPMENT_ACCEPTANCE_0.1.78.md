## 版本、源码和启动

本轮主工程为本仓库的 `gems/`，沿用 Electron、React、TypeScript、SQL.js 和实验性 C# 助手。原工程及上一轮整理副本保留；本轮核对原工程355个文件，未发现内容变化。完整原需求已从旧聊天恢复，45节、65项功能、A—H场景和123项历史记录均保留在 [验收清单](../gems/docs/ACCEPTANCE_MATRIX.md)。历史“通过”不自动计入本轮。

交付目录为 `gems/release/`：开发安装器 `GEMS-0.1.78-dev.1-x64-setup.exe`、便携包 `GEMS-0.1.78-dev.1-x64-portable.exe`、源码包 `GEMS-0.1.78-dev.1-source.zip`。逐文件SHA-256及未签名状态以同目录实际生成的 `manifest.json`、`SHA256SUMS.txt` 为准。源码包不含游戏资产、第三方模组、个人证据、SDK二进制或秘密信息。实验性助手构建产物位于 `gems/native/game-assistant/artifacts/`，不自动部署进游戏。

- 使用开发安装器按向导安装后运行 GEMS；便携版可直接启动。两者均为未签名开发产物。若系统拒绝运行，保留具体错误，不修改系统保护设置。
- 首次进入应用先选择 Enhanced 游戏目录并检查诊断结果。导入只生成扫描记录，不会自动安装。选择模组后预览写入目标、覆盖和依赖，再执行受限文件安装；停用/卸载按该事务恢复。遇到外部更改保留文件并显示恢复待处理。
- RPF替换只导出未加密普通二进制条目的独立副本；不等于将资源转换或安装到游戏。DLC注册、真实Legacy转换及尚未支持的操作继续禁用。
- 默认用户数据为 `%APPDATA%\GEMS\Studio`；卸载软件不代表卸载已安装到游戏的模组。实际游戏模组须先按应用事务停用/卸载并验证恢复。
- 从源码运行：Windows x64、Node.js 24，在 `gems/` 执行 `npm ci`、`npm test`、`npm run build`、`npm start`。归档后端与打包说明见 [ARCHIVE_BACKEND.md](../gems/docs/ARCHIVE_BACKEND.md)，助手另见其 [构建说明](../gems/native/game-assistant/BUILDING.md)。

## 未完成和游戏阻塞

本轮**没有向真实游戏目录写入、没有进入故事模式、没有证明任何模组实际加载、使用或恢复后游戏正常**。当前1.0.1158.16与本轮已核Script Hook V支持记录1.0.1158.13不匹配，本机也未发现所需加载器/脚本运行时。不能以近邻版本推断兼容。用户已有M4资源仅用于只读分析，未安装或转换。

实现缺口仍包括真实Legacy转换、DLC注册/加密RPF、模型纹理预览、完整类别和语义冲突、配置方案/纯净模式、分组二分诊断、完整游戏助手及三类实时同步、完整跨站下载更新、日志/数据库维护、插件、自动更新和50包全链。完整范围、各项条件及未测试场景以验收清单为准，没有取消或缩减需求。

接续先完成不依赖游戏的剩余实现和测试。游戏实测需要：确认当前版本能进入故事模式；确定精确匹配的合法运行时及加载器；选择有权使用的代表性样本并建立恢复点。之后逐类执行“导入→依赖检查→安装→故事模式加载与实际功能→退出→停用/卸载恢复→再次检查”，记录版本、样本、依赖、日志及截图/录像。需要用户操作时只要求对应步骤和结果，不要求以重装游戏或清空模组目录代替恢复。
